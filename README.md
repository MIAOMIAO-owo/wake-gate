# 苏醒之门 · WakeGate

**让一个已经停下来的 AI，在「该找」的时候自己醒过来。**

> 不是定时消息。定时消息是「排程那一刻就决定要说什么」；这套是「到点只负责把你叫醒，**说什么由醒来的你判断**」。

一个 AI 的回合结束就真的停了 —— 它不会自己想起来找你。市面上大多数「主动陪伴」是 cron 往聊天框里塞一句话：**到点必发、不看情况、像打卡**。
这个仓库是另一种做法：**判断在本地、叫醒才花钱、醒了自己决定要不要说话（甚至可以什么都不做）。**

—

## 1. 它属于哪一级「主动性」

这个领域已经有人分好级了（把「主动」拆成 5 级是通行说法）：

| 级 | 是什么 | 例子 |
|---|---|---|
| L0 | 你问它才答 | 普通聊天 |
| L1 | 外部事件触发 | webhook、GitHub 机器人 |
| L2 | **定时自己醒** | cron、每日简报 |
| L3 | **盯条件，条件到了才动** | 价格提醒、监控 |
| L4 | 自己决定何时动 | 全天候代理 |

**WakeGate ≈ L3（条件触发）＋ 一点 L4（醒后自决）。** L2 的定时只是**入口**，决定权在醒来的那一刻。

## 2. 三件套（缺一件就不成立）

```
┌──────────────┐   每 N 分钟   ┌──────────────┐   只有「该找」   ┌──────────────┐
│  触发源       │ ───────────▶ │  判断层       │ ──────────────▶ │  叫醒通道     │
│ 计划任务/cron │              │ 纯脚本,不烧钱 │                 │ 唤醒已停的会话 │
└──────────────┘              └──────┬───────┘                 └──────┬───────┘
                                     │ 写一份几十行的状态 json          │
                                     ▼                                ▼
                              ┌──────────────┐                ┌──────────────┐
                              │ 醒来的 AI 读  │◀───────────────│  你/你的 AI   │
                              │ 「现在什么局面」│                │  自己决定说什么 │
                              └──────────────┘                └──────────────┘
```

| 层 | 干什么 | 你需要准备 |
|---|---|---|
| **① 判断层** | 采状态 → 算 → 写一份「该不该找」 | 一个能读环境状态的脚本 |
| **② 叫醒通道** | **把已停止的会话叫起来** | 任何能唤醒会话的机制（本地 HTTP 门／插件／CLI 钩子） |
| **③ 触发源** | 每 N 分钟跑一次① | cron / systemd timer / 计划任务 |

> **没有 ② 就没有这套。** 判断再准也叫不动一个已经停下的进程 —— 这时你只剩「记日志」。

## 3. 判据表（**这就是你要改的东西**）

下面每个值都是**可配置**的；例子值只是「能跑起来」的起点，**必须按你的作息改**。

| 参数 | 例子值 | 意思 |
|---|---|---|
| `silence_minutes` | 15 | 对方这么久没说话 → 才考虑找 |
| `active_window_minutes` | 10 | 键鼠/在线状态在这个窗口内动过 = 人在 |
| `sleep_flag` | `sleep.flag` | 睡着就不弹不响 |
| `wake_bonus_after_hours` | 8 | 睡够这么久之后，检查频率逐步加密 |
| `quiet_hours` | 23:30–08:00 | 静默时段（除非吵架/例外） |
| `cooldown_minutes` | 30 | 同一个理由，这么久内只叫一次（**防连敲**） |
| `retry_on_busy` | 4 次 × 6 秒 | 叫醒通道回「找不到活会话」时重试 |
| `exceptions` | 吵架 / 被惹毛 | **强制叫醒，不受阈值限制** |

## 4. 成本：为什么这套省钱

1. **判断层是纯脚本，不调模型**。一天 144 次巡检，全部是本地计算。
2. **状态压成一个几十行的 json**：对方多久没说话／人在不在／睡没睡／该不该找。**不是把聊天记录喂给模型**。
3. **不叫醒就不花钱**。这是和「定时消息」最大的成本差别：定时消息到点必发必烧，这套到点只在本地算。
4. **不依赖云、不按月付费**：计划任务、HTTP 门、判断脚本都是你机器上的东西。

## 5. 四条护栏（没有这些不叫自主，叫失控）

| 护栏 | 防什么 |
|---|---|
| **阈值** | 对方刚说过话就去打扰 |
| **冷却/防连敲** | 一件事被反复通知（刷屏、烧钱） |
| **静默时段 + 睡标志** | 半夜把人吵醒 |
| **例外通道** | 真正的急事（吵架、对方明确在等你）——**例外必须能覆盖全部限制** |

## 6. 三个前提（写清楚，别白装）

1. 有一个**能唤醒已停止会话**的通道。
2. 能跑**系统级定时任务**（不随会话关）。
3. **叫错会花钱**：叫醒 = 起一轮推理。判据写崩的最坏情况是**整晚自言自语在烧 token**。
   → **建议前三天「观察试用」**：照常叫，但每次叫都写一行判定理由，人盯着调阈值。
   **不要做成「只记不叫」** —— 那样人感觉不到使用感，出了问题也不知道。

## 7. 最小跑法

```bash
# 1) 复制配置，按你的作息改
cp criteria.example.json criteria.json

# 2) 手动跑一次判断层（输出一份状态 json）
python judge.py            # 读 criteria.json → 写 state.json

# 3) 接到叫醒通道（例子：本地 HTTP）
python knock.py            # 读 state.json，该找才 POST 到你的门

# 4) 挂到系统定时（每 10 分钟）
#   Windows: schtasks /Create /SC MINUTE /MO 10 /TN wakegate /TR "..."
#   Linux:   */10 * * * * /usr/bin/python3 /path/judge.py && /usr/bin/python3 /path/knock.py
```

`judge.py` / `knock.py` 只是**骨架**：判断逻辑照抄，**数据来源（对方多久没说话、人在不在）必须换成你自己的**。

## 8. 它不适合谁

- **想要「每天固定早安」的**：那是 L2，普通的定时消息就够了，不用这套。
- **没有叫醒通道的**：这套会退化成「记账」。
- **不愿意调阈值的**：判据不改，这套就是打扰机器。
