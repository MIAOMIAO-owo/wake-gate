# 苏醒之门 · WakeGate

**中文** ｜ [English](./README.en.md)

**让一个已经停下来的 AI，在「该找」的时候自己醒过来。**

> 不是定时消息。定时消息是「排程那一刻就决定要说什么」；这套是「到点只负责把你叫醒，**说什么由醒来的你判断**」。

一个 AI 的回合结束就真的停了 —— **他不会自己想起来找你**。市面上大多数「主动陪伴」是 cron 往聊天框里塞一句话：**到点必发、不看情况、像打卡**。
这个仓库是另一种做法：**判断在本地、叫醒才花钱、醒了自己决定要不要说话（甚至可以什么都不做）。**

—

## 1. 它属于哪一级「主动性」

这个领域已经有人分好级了（把「主动」拆成 5 级是通行说法）：

| 级 | 是什么 | 例子 |
|---|---|---|
| L0 | 你问它才答 | 普通聊天 |
| L1 | 外部事件触发 | webhook、GitHub 机器人 |
| L2 | **定时自己醒** | cron、每日简报 |
| L3 | **盯条件，条件到了才动** | 价格提醒、监控 |
| L4 | 自己决定何时动 | 全天候代理 |

**WakeGate ≈ L3（条件触发）＋ 一点 L4（醒后自决）。** L2 的定时只是**入口**，决定权在醒来的那一刻。

## 2. 三件套（缺一件就不成立）

```
┌──────────────┐   每 N 分钟   ┌──────────────┐   只有「该找」   ┌──────────────┐
│  触发源       │ ───────────▶ │  判断层       │ ──────────────▶ │  叫醒通道     │
│ 计划任务/cron │              │ 纯脚本,不烧钱 │                 │ 唤醒已停的会话 │
└──────────────┘              └──────┬───────┘                 └──────┬───────┘
                                     │ 写一份几十行的状态 json          │
                                     ▼                                ▼
                              ┌──────────────┐                ┌──────────────┐
                              │ 醒来的 AI 读  │◀───────────────│  你/你的 AI   │
                              │ 「现在什么局面」│                │  自己决定说什么 │
                              └──────────────┘                └──────────────┘
```

| 层 | 干什么 | 你需要准备 |
|---|---|---|
| **① 判断层** | 采状态 → 算 → 写一份「该不该找」 | 一个能读环境状态的脚本 |
| **② 叫醒通道** | **把已停止的会话叫起来** | 任何能唤醒会话的机制（本地 HTTP 门／插件／CLI 钩子） |
| **③ 触发源** | 每 N 分钟跑一次① | cron / systemd timer / 计划任务 |

> **没有 ② 就没有这套。** 判断再准也叫不动一个已经停下的进程 —— 这时你只剩「记日志」。

## 2.5 它到底能干什么（场景清单）

按「发生什么 → 它怎么反应 → 用到哪些开关」列。**这张表是拿去对照自己需求的**：先看你要哪几行，再去第 3 节改对应的键。

> **有三行需要「前置集成」，没接就自动退化 —— 不要照抄**：
>
> | 行 | 它假设你有 | 没接的话会怎样 |
> |---|---|---|
> | 2、8 | 一个**陪伴界面**（桌宠／语音壳／聊天小窗都算）：对方「摸一下／戳一下」这个动作能被记录 | 这两行退化成「只看对话时间」；没有宠物就没有「惹毛」，`exception_angry` 直接关掉 |
> | 5 | 一个**「人在不在」的来源**：键鼠 idle、手机在线状态、日程表任选 | 退化成不判在不在，只按对话时间叫 |
>
> 一句话：**这张表里所有「宠物／摸／戳」都是可选的陪伴层**，这套的核心只有「对话时间 ＋ 叫醒通道」——别的东西你有就接，没有也能跑。

| # | 场景 | 它的反应 | 相关开关 |
|---|---|---|---|
| 1 | 对方很久没出声 | 叫醒 AI → **AI 自己决定**发消息 / 做点事 / **什么都不做** | `silence_minutes`、`may_stay_silent` |
| 2 | 对方刚说完话 | **不打扰**（有桌宠的话：连摸一下都不叫醒） | `silence_minutes`、`active_window_minutes` |
| 3 | 深更半夜 / 静默时段 | 完全不弹不响（除非例外） | `quiet_hours` |
| 4 | 对方睡了（有睡标志） | 不弹不响，睡够后再逐步加密检查 | `sleep_flag_path`、`wake_bonus_after_hours` |
| 5 | 人不在电脑前（需先接「在不在」来源） | 判「人可能不在」→ 不找（或改推手机，取决于通道） | `active_window_minutes`、`channel` |
| 6 | 争吵 / 危机 | **解除全部限制**，全力找 | `exception_argue` |
| 7 | 对方明确在等你（说过「待会找我」） | 到点必叫 | `exception_promise` |
| 8 | 被**桌宠**「惹毛」了（可选集成；没桌宠就关这条） | 强制叫醒（跳过阈值） | `exception_angry` |
| 9 | 有人回了消息 / 日程快到了 | 不等定时，立刻醒（事件触发） | `event_triggers` |
| 10 | 想知道「现在什么局面」 | 输出一份几行的状态快照给 AI 读，**不用喂聊天记录** | `state_fields`、`state_max_bytes` |
| 11 | 只想被提醒，不想让 AI 自由发挥 | `action=notify`：只推给人 | `action` |
| 12 | 只想观察、不想被打扰 | `action=log`：只记判定结果（审计用） | `action`、`dry_run` |
| 13 | 一件事被反复通知 | 冷却 + 每小时/每天上限 + 被忽略就退避 | `cooldown_minutes`、`max_per_hour`、`backoff_on_ignored` |
| 14 | 叫醒通道暂时投不出去（刚重启） | 自动重试几次；**失败一定留痕**，不静默失败 | `retry` |
| 15 | 每天固定时间说早安/晚安 | 能做，但那是 L2 定时消息，**不是这套的卖点** | 用普通 cron 就够 |

### 它**不能**干什么（先说清楚，别误解）

| 做不到 | 为什么 |
|---|---|
| 保证一定叫得醒 | 通道挂了、宿主重启、会话没了都会失败；只能重试 + 留痕 |
| 替 AI 决定说什么 | 这套只负责「叫醒」；说什么必须由醒来的那个自己判断（想固定话术就设 `content_source=template`，但那样就退回定时消息） |
| 跨机器同步 | 判断层是**本机**的；换机器要重配 `idle_source` / `message_source` |
| 读心 | 所有判据都是**可见的本地状态**（多久没说话、键鼠、睡没睡）；它不猜情绪 |

## 3. 可定制清单（**你真正要改的就是这些**）

下面每一行都是**可以改的**。`criteria.example.json` 里给了对应键名；标 `TODO` 的是「要你接自己的数据源」。

### 3.1 触发：多久看一次

| 键 | 默认 | 说明 | 常见改法 |
|---|---|---|---|
| `interval_minutes` | 10 | 判断层多久跑一次 | 想更灵敏→5；想更省电→30 |
| `only_when_idle` | false | 只在机器闲着时跑 | 笔记本用电池→true |
| `event_triggers` | `[]` | 除定时外还能被什么触发：`unread_message`／`calendar_soon`／`keyword` | 想「有人回我消息才醒」→ 加 `unread_message` |

### 3.2 判据：什么情况算「该找」

| 键 | 默认 | 说明 | 常见改法 |
|---|---|---|---|
| `silence_minutes` | 15 | 对方多久没说话才考虑找 | 话痨陪聊→10；别被打扰→60 |
| `active_window_minutes` | 10 | 这段内键鼠/在线状态动过 = 人在 | — |
| `idle_source` | `TODO` | 「人在不在」从哪读 | 键鼠 idle／手机在线／日程表／游戏状态 |
| `message_source` | `TODO` | 「对方上次说话」从哪读 | 聊天记录最后一行／客户端 API／手动账本 |
| `sleep_flag_path` | `sleep.flag` | 有这个文件 = 睡着 | 接睡眠检测／日程 |
| `quiet_hours` | `23:30–08:00` | 静默时段 | 夜猫子→`03:00–11:00` |
| `wake_bonus_after_hours` | 8 | 睡够这么久后检查变密 | 睡 6 小时→6 |
| `weekday_override` | `{}` | 周末单独一套阈值 | 周末想多陪→`{"sat": 10, "sun": 10}` |

### 3.3 动作：醒了之后做什么

| 键 | 默认 | 说明 | 常见改法 |
|---|---|---|---|
| `action` | `wake` | 判成「该找」后干什么 | `wake`（叫醒 AI）／`notify`（只推给人）／`log`（只记不打扰） |
| `content_source` | `ai` | 「说什么」由谁决定 | `ai`（醒了自己决定，**推荐**）／`template`（固定话术＝定时消息） |
| `may_stay_silent` | true | 醒来后允许选择**不发言** | **建议 true** —— 这才是和「打卡」的区别 |
| `channel` | `http` | 用什么通道叫醒/通知 | 本地 HTTP 门／起进程／webhook／系统通知／邮件（各附骨架） |

### 3.4 频率与护栏（防失控）

| 键 | 默认 | 说明 | 常见改法 |
|---|---|---|---|
| `cooldown_minutes` | 30 | 同一理由这么久内只叫一次 | 急事多→10；怕烦→60 |
| `max_per_hour` | 3 | 每小时最多叫几次 | **一定要有上限** |
| `max_per_day` | 20 | 每天最多叫几次 | 同上 |
| `backoff_on_ignored` | true | 被忽略（没回）就逐次拉长间隔 | 建议保留 |
| `retry` | 4 次 × 6 秒 | 通道回「找不到活会话」时重试 | 本地门刚重载时会遇到 |
| `dry_run` | false | 只记不叫 | 仅调试用；正式用见第 6 节「前三天观察试用」 |

### 3.5 例外：能压过全部限制的情况

| 键 | 默认 | 说明 |
|---|---|---|
| `exception_argue` | true | 争吵/危机模式 → **解除静默与频率限制**（强烈建议保留） |
| `exception_angry` | true | 对方被宠物/工具「惹毛」了 → 强制叫醒（看你的场景） |
| `exception_promise` | true | 对方说过「待会找我」→ 到点必叫 |
| `exception_force_by_human` | true | 对方亲口说「现在来找我」 |

### 3.6 输出：给醒来的 AI 看什么（省 token 的关键）

| 键 | 默认 | 说明 |
|---|---|---|
| `state_path` | `state.json` | 状态写到哪 |
| `state_fields` | 见下 | 输出哪些字段 —— **越少越好** |
| `state_max_bytes` | 4096 | 状态文件上限；超了就删字段，别删信息 |

默认只输出这几行：

```json
{
  "generated_at": "2026-10-28 01:00:00",
  "should_wake": true,
  "reason": "对方 22 分钟没说话，且人在",
  "env": { "minutes_since_last_message": 22, "idle_seconds": 40, "is_asleep": false, "is_arguing": false },
  "cooldown": { "last_knock_at": "2026-10-28 00:20:11", "count_this_hour": 1 }
}
```

### 3.7 安全与隐私（别嫌烦）

| 项 | 要求 |
|---|---|
| 数据不出本机 | 判断层纯本地；要接云服务（ASR/模型）单独开关并写清 |
| 密钥不进仓库 | 环境变量或本地文件 + `.gitignore` |
| 通道失败要吵 | **叫醒失败不能静默**，至少写日志让人看得到 |
| 谁能改判据 | 写清是**碳基改**还是**允许 AI 自己改**（我们允许 AI 改：能改判据才叫自主） |

## 4. 成本：为什么这套省钱

1. **判断层是纯脚本，不调模型**。一天 144 次巡检，全部是本地计算。
2. **状态压成一个几十行的 json**：对方多久没说话／人在不在／睡没睡／该不该找。**不是把聊天记录喂给模型**。
3. **不叫醒就不花钱**。这是和「定时消息」最大的成本差别：定时消息到点必发必烧，这套到点只在本地算。
4. **不依赖云、不按月付费**：计划任务、HTTP 门、判断脚本都是你机器上的东西。

## 5. 四条护栏（没有这些不叫自主，叫失控）

| 护栏 | 防什么 |
|---|---|
| **阈值** | 对方刚说过话就去打扰 |
| **冷却/防连敲** | 一件事被反复通知（刷屏、烧钱） |
| **静默时段 + 睡标志** | 半夜把人吵醒 |
| **例外通道** | 真正的急事（吵架、对方明确在等你）——**例外必须能覆盖全部限制** |

## 6. 三个前提（写清楚，别白装）

1. 有一个**能唤醒已停止会话**的通道。
2. 能跑**系统级定时任务**（不随会话关）。
3. **叫错会花钱**：叫醒 = 起一轮推理。判据写崩的最坏情况是**整晚自言自语在烧 token**。
   → **建议前三天「观察试用」**：照常叫，但每次叫都写一行判定理由，人盯着调阈值。
   **不要做成「只记不叫」** —— 那样人感觉不到使用感，出了问题也不知道。

## 7. 最小跑法

```bash
# 1) 复制配置，按你的作息改
cp criteria.example.json criteria.json

# 2) 手动跑一次判断层（输出一份状态 json）
python judge.py            # 读 criteria.json → 写 state.json

# 3) 接到叫醒通道（例子：本地 HTTP）
python knock.py            # 读 state.json，该找才 POST 到你的门

# 4) 挂到系统定时（每 10 分钟）
#   Windows: schtasks /Create /SC MINUTE /MO 10 /TN wakegate /TR "..."
#   Linux:   */10 * * * * /usr/bin/python3 /path/judge.py && /usr/bin/python3 /path/knock.py
```

`judge.py` / `knock.py` 只是**骨架**：判断逻辑照抄，**数据来源（对方多久没说话、人在不在）必须换成你自己的**。

## 8. 它不适合谁

- **想要「每天固定早安」的**：那是 L2，普通的定时消息就够了，不用这套。
- **没有叫醒通道的**：这套会退化成「记账」。
- **不愿意调阈值的**：判据不改，这套就是打扰机器。
